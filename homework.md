1. package.json

This is the main project configuration file.

What it contains

Project metadata (name, version, description)

Scripts (npm start, npm run build)

Dependencies you want to install

Dev dependencies

Version ranges of packages

Example:

{
"name": "my-app",
"version": "1.0.0",
"dependencies": {
"express": "^4.18.2"
}
}
Key point

The version here is usually a range, not an exact version.

Example:

^4.18.2 → allows installing 4.x.x newer versions

~4.18.2 → allows patch updates

4.18.2 → exact version

So the actual installed version may vary.

2. package-lock.json

This file is automatically generated by npm and records the exact versions installed.

What it contains

Exact dependency versions

Sub-dependencies versions

Integrity hashes

Resolved URLs

Example snippet:

{
"name": "my-app",
"lockfileVersion": 3,
"dependencies": {
"express": {
"version": "4.18.2",
"resolved": "...",
"integrity": "sha512-..."
}
}
}
Key point

It locks dependencies so everyone installs the same versions.

Real Example Scenario

In package.json:

"express": "^4.18.2"

Possible install:

Time Installed Version
Today 4.18.2
After update 4.19.0

But package-lock.json ensures everyone installs 4.18.2 exactly.

Why package-lock.json is important

It guarantees:

Same dependencies for all developers

Same build in CI/CD

No “works on my machine” issues

Faster installs (npm ci)

Quick Comparison
Feature package.json package-lock.json
Created by Developer npm automatically
Purpose Define dependencies Lock exact versions
Version type Range (^, ~) Exact version
Should commit to git? Yes Yes
Editable manually? Yes Not recommended
